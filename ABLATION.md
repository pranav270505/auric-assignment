# Ablation

All numbers are macro exact match (the mean of the unique, ambiguous and
inconsistent rates, `score.py`). Model: `ibm-granite/granite-4.2-8b`,
temperature 1.0, top_p 0.95, reasoning off. One item is 1.7 points; two live
1x runs of the same system have differed by up to 6.7 points, so differences
of one or two items are within run-to-run noise. Every cell states how many
runs it comes from.

## 1. Live ablation, visible set

Reproduce with `python3 ablate.py live --budgets 1x,3x,10x` (each cell is one
independent live run through the endpoint; component switches are the
`--ablate` flags of `run.py`). "n/a": the component only acts when there are
several samples, so at 1x the arm is identical to the full system.

| Component | 1x | 3x | Runs |
|---|---|---|---|
| **full system** | **93.3%** | **96.7%** | 1 + 1 |
| − hedge stripping | 81.7% | 95.0% | 1 + 1 |
| − robust parser | 93.3% | 96.7% | 1 + 1 |
| − grounding check (and re-grounding) | 85.0% | 86.7% | 1 + 1 |
| − re-grounding only | 91.7% | 96.7% | 1 + 1 |
| − voting (1 sample) | n/a | 95.0% | 1 |
| − reversed-order samples | n/a | 98.3% | 1 |
| − rescue | n/a | 95.0% | 1 |
| − core flip | 93.3% | 96.7% | 1 + 1 |
| + self-check repair (removed) | n/a | 96.7% | 1 |
| + named slots (not adopted) | 95.0% | 98.3% | 1 + 1 |

Full system at 10x, live: **100.0%** (one run; the final code re-deciding the
saved outputs of an earlier 10x run scores 98.3%). A second live run of the full system on a
later day scored 91.7% at 1x and 95.0% at 3x, so the full-system rows are
best read as 92.5% (1x) and 95.8% (3x), mean of two runs.

The core flip never triggers on the visible set (no visible item produced a
one- or two-line contradiction), so its row equals the full system by
construction. Its effect shows on the held-out sets (section 2).

## 3. Generalisation

Four test sets, all scored with `score.py`:

| Set | What it tests | 1x | 3x | 10x | Runs |
|---|---|---|---|---|---|
| Visible | the 60 given items | 92.5 (91.7, 93.3) | 95.8 (95.0, 96.7) | 100.0 | 2 / 2 / 1 |
| Paraphrase | same puzzles, every clue reworded | 90.0 (90.0, 90.0) | 93.3 (95.0, 91.7) | – | 2 / 2 |
| Fresh | new puzzles and names, wording pool A, visible-set difficulty | 84.2 (83.3, 85.0) | 88.3 (88.3, 88.3) | – | 2 / 2 |
| Fresh2 | new puzzles, wording pool B, written after the error analysis | 65.0 (66.7, 63.3) | 70.8 (71.7, 70.0) | – | 2 / 2 |

The private held-out set uses new puzzles and an unseen phrasing pool, so the
fresh and fresh2 rows are the best estimate of it: roughly 65–84% at 1x and
71–88% at 3x depending on how unfamiliar the wording is. The extraction prompt
was tuned on the visible set only. The core flip was chosen after checking
candidate post-processing rules on saved runs of all four sets; it was the
only one that never lowered a score (23 runs: 8 better, 0 worse). The paraphrase and
fresh sets are generated by `dev/make_paraphrase_set.py` and
`dev/make_fresh_set.py`; `dev/check_fresh.py` verifies each key against the
solver and checks that no clue wording is shared with `items.json` or the
prompt. For runs made before the core flip existed, the numbers above are the
final code re-deciding those runs' saved model outputs; the core flip is
deterministic post-processing, so this equals a live run of the final system
on those outputs.

## 4. Named slots: built, measured, not adopted

Writing ordered rules as `before(earlier=A, later=B)` was meant to stop
argument-order reversals. Live, same day, same items (`--ablate with_slots`):

| Set | 1x positional | 1x named slots | 3x positional | 3x named slots |
|---|---|---|---|---|
| Visible | 91.7 | 95.0 | 95.0 | 98.3 |
| Paraphrase | **90.0** | 83.3 | **93.3** | 88.3 |
| Fresh | **81.7** | 73.3 | **86.7** | 80.0 |
| Fresh2 | 66.7 | **78.3** | 71.7 | **83.3** |
| Mean, three held-out sets | **79.5** | 78.3 | 83.9 | 83.9 |

The fresh2 gain reproduced in an earlier pair of runs (+13.4 at 1x, +11.7 at
3x); the paraphrase and fresh comparisons are one pair of runs each. Per clue type, named slots cut reversals of plain `before`
clues (fresh2: 21% → 13% error) but raised reversals of station-first clues
(fresh: 1% → 4%). On unseen wording the two formats tie, so the simpler
positional format stays the default.

## 5. Development history

| Version | Change | Visible 1x | 3x | 10x |
|---|---|---|---|---|
| v1 | extraction + solver, strict parser | 71.7 | | |
| v2 | robust parser, grounding, self-check repair | 81.7 | 81.7 | 80.0 |
| v3 | prompt fixes, reversed-order samples, rescue; self-check removed | 85.0 | 96.7 | 96.7 |
| v4 | re-grounding | 93.3 | 96.7 | 100.0 |
| final | core flip (no change on visible; +1.6 to +1.7 on fresh and paraphrase 3x) | 92.5 (2 runs) | 95.8 (2 runs) | 100.0 |

v2's flat curve is the central finding: Granite's extraction errors are
systematic (the same line misread in every sample), so plain voting could not
fix them; v3 onwards attacks the systematic part directly.
